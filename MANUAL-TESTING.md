# Manual test checklist

Everything automation cannot prove. Tick each box as you verify it; write the
result in the Notes column so a half-finished pass is still useful to the next
person.

**Why this exists:** `pnpm test` passes on code that cannot record at all. It
has done so twice in this project's history — once when every chunk exceeded the
DataChannel message limit, and once when the deployed bundle called `localhost`.
A green suite means the units behave; it says nothing about whether a recording
lands on disk.

---

## Setup

You need **two separate browser profiles** (not two tabs — the host token lives
in `localStorage`, so a second tab of the same profile is also the host).

```bash
pnpm install
pnpm --filter @openmeet/worker db:migrate:local
pnpm --filter @openmeet/worker dev     # terminal 1 → :8787
pnpm --filter @openmeet/web dev        # terminal 2 → :3000
```

- **Host:** normal Chrome window. Click **New Room**.
- **Guest:** a second Chrome profile, or Incognito, opening the invite link.

Record with **Chromium**: Chrome, Edge, Arc or Opera (Brave hosts only after
enabling brave://flags/#file-system-access-api). Firefox can't record. Safari can't
host, and a Safari guest is recorded as video only (no WAV).

Keep DevTools **Console open on both sides** for every test below. Most of the
bugs this checklist targets are silent by nature — the console is where they
show up first, if at all.

### Inspecting the output

```bash
ffprobe -v error -show_entries format=duration,size \
  -show_entries stream=codec_name,width,height,sample_rate \
  -of default=noprint_wrappers=1 <file>
```

For a WAV, check the header's declared size matches the file:

```bash
python3 - <<'EOF'
import struct, os, sys
f = sys.argv[1] if len(sys.argv) > 1 else input('wav path: ')
d = open(f,'rb').read(80)
# RF64 files (past 4 GiB) hold the data size at 28 as 64 bits; others hold it at 76.
declared = struct.unpack('<Q', d[28:36])[0] if d[:4] == b'RF64' else struct.unpack('<I', d[76:80])[0]
print('first chunk   =', d[12:16].decode())
print('declared data =', declared)
print('actual data   =', os.path.getsize(f) - 80)
EOF
```

## Known limitations — not bugs, do not file

- **Recording needs Chromium.** Firefox can't record. Safari can't host, and a
  Safari guest is recorded as video only (no WAV). Brave hosts only after enabling
  brave://flags/#file-system-access-api.
- **A camera file can hold less than the bitrate its level names.** The figure in the
  lobby ("up to 5 Mbps") is what the encoder is asked for. Chrome on Linux has only a
  software H.264 encoder, which spends that figure over 60 frames a second whatever the
  camera delivers: a 30 fps file holds about half of it, a 24 fps file about 40%.
  Not measured on macOS or Windows.
- **Phones can't share a screen.** They present a photo, a video or the rear
  camera; a real screen comes from a second device joined with **Present only**.
- **Mid-take camera or mic switching needs Chromium.** Safari and iPhone switch
  between takes.
- **A screen file ends where its connection did** when the share is stopped while the
  connection is down, on a page that reloads, when the stream was given up or is being
  sent later, when the host started another take or reloaded and resumed, and for a
  ninth file waiting in one take. The summary marks it incomplete and the rest is only
  in the sharer's screen backup.
- **A second host tab mid-take asks before it takes the call over.** If the host
  joins there anyway, the first tab's files end there; the rest of each guest's
  part is only in that guest's backup. After its End & save the old tab still offers
  **Record another take**, which would record that tab alone: press **Leave call**.
- **A pad played with the microphone off isn't recorded in a take that was already
  running when the media board was first opened.** It is heard and drops its marker;
  the next take records it either way. On Safari and iPhone that take records no pads.
- **A take started with the media board open has two audio channels in its camera MP4,**
  also when the lobby says Mono, so stereo pads keep their stereo. The voice is
  the same on both channels, and the WAV master stays mono. A take that was already
  running when the board was first opened keeps the channels it started with.
- **Clock sync needs one answer from the host while the guest is recording.** The
  guest keeps asking; with no answer before its recording ends, `sync.json` has no
  offset for it and says to align by waveform.
  A guest whose clock is seen set back before its first estimate stops asking,
  with the same result.
- **A computer clock set during a take, before a guest's first estimate, shifts that
  guest's offsets** by the size of the change, and nothing in `sync.json` shows it. A
  first estimate that arrives after a resume is lost if the host's browser closes again.
- **A WAV master past 4 GiB is RF64.** Its header is an RF64 one with 64-bit sizes, which
  ffmpeg and most audio editors read in full; Python's `wave` module and other tools that
  read only plain WAV refuse it. A WAV whose 44-byte header has no reserved chunk still
  declares 4 GiB past that point, and only ffmpeg reads it to the end.
- **After many stalls the WAV is a little shorter than the MP4:** a real gap can be
  filled one frame short.
- **openMeet records no FLAC.** The sync file gives the commands; a WAV that reads Empty
  still has them. A WAV backup downloaded by a participant shows no command (they are in
  the README), and a returned backup's are only in its `.json`.
- **No TURN configured** means two people behind strict NATs cannot connect.
- **A host's mute turns off the microphone only.** That person's media board pads
  and the sound of a video they present keep playing.
- **Nobody else is told why a person left;** a removal looks like any leave. Mute and
  remove are on the call screen only, and a person muted while their page still reads
  "Connecting…" sees the mic button there as on.
- **A removed participant can come back in another tab.** The room keeps out the tab
  the host removed until everyone has left. Unless the host has locked the room, turned
  the waiting room on or set a passcode, the invite link is the only credential, so
  another tab, a private window or another browser joins again.
- **A guest whose browser blocks session storage counts as another tab on every
  reload:** the host's "not recorded" for them is forgotten, and a removed one gets back
  in by reloading.
- **A removed participant who presses Leave call instead of Stop and save reads "You
  left the call",** and its **Rejoin** ends on "The host removed you from this call".
- **While a removed participant's save runs, the notice reads "Sending your last few
  seconds to the host."** Nothing is sent. A backup they were sending back stays
  stalled on the host, and a Present-only device removed during a take gets no
  download link.
- **A room name is never freed.** Once a named room has expired its link reads "Room
  not found or expired", and choosing the same name again reads "That name is taken.
  Choose another."
- **A room expires 30 days after its last call.** Opening a check link (`?check=1`) or
  the record-alone page joins nothing, so neither keeps a room alive; a check link of an
  expired room reads "Room not found or expired".
- **The producer, Present-only, microphone-only, view and record-alone links are copied
  only from the host's waiting room and from the arrow in the call's top bar before a
  take.** The lobby, the take summary and the top bar during or after a take offer the
  plain invite link alone. A guest's view link is also under **People**.
- **A view link takes one of the two unrecorded places.** Refused at the cap it reads
  "This room is full" until the page is reloaded. A view left open keeps the session
  going; a Help ask sent to it does nothing; opened on a computer that is in the call it
  plays the person a second time (mute that tab). Of two people with one name, the one
  listed first is shown.
- **The done screen has no Copy invite link.** The address in the address bar is the
  invite link.
- **A lock ends with the session.** When everyone has left, or every connection drops
  at once, the room is open again. A person whose browser blocks session storage reads
  "This room is locked" after a reload.
- **The waiting room holds tabs, not people.** Anyone with the link can fill its eight
  places with names of their choosing, and the next person reads "Too many people are
  waiting"; a refused person can knock again. A person whose own recording is running
  when their reconnect is held keeps the call screen and is told nothing until let in.
- **A passcode is shown nowhere and is not in the invite link.** A host who forgot it
  removes it and sets another. After 20 wrong tries everyone else who comes, also with
  the right passcode, reads "Too many wrong passcodes" for up to ten minutes; the people
  in the call are not affected. A passcode does not hide that the room exists.
- **After a host reload and Resume:** the host's timer starts again at 0:00; a guest's
  running screen share is not recorded until they share again, and only the host is
  told; the host's own screen is recorded only from its next share; a screen recording
  that had finished reads "rebuilt" and "ended early" though the file is whole; the
  host's own camera file from before the reload can end a few seconds before its WAV;
  call-audio copies from before the reload are not in the report; the host's files
  after the reload carry no name (`host_<id>_resumed.*`).
- **Resume copies each guest file once more,** so a long take takes a while to resume
  and needs the file's size free on the disk.
- **With several guests in the room, none is told that the host dropped;** only a guest
  left alone reads that the host can resume.
- **After a host reload a guest can read "Sent to the host." for a part the host never
  wrote,** when the host then saves instead of resuming. The summary says that file
  ended early; the guest's backup has all of it.
- **A guest who joined a take just before the host's connection came back can get two
  files.** While the host's connection is down, a guest who joins is not recorded; they
  start when the host is back.
- **After a Save or Delete from the lobby, the guests stop recording only when the host
  joins.**
- **A crash copy is reached only from its own room's lobby,** and stays in browser
  storage after the room expires. A lobby opened in another tab right after Record can
  remove the take's empty crash copy; the take then says its crash protection stopped. A
  file whose crash copy stopped on a storage write that never answered still offers
  Resume, which cannot go past where the copy stopped.
- **A take saved from the lobby after a crash** holds what a guest sent before they
  were set as not recorded, has no `nameTags` and no echo-cancellation mark, and lists a
  file recorded with no camera as a camera file, whose pairing command `ffmpeg` refuses.
  The lobby's Save does not copy the host's own screen backup.
- **A take recorded alone is not listed as Unsaved recording after a crash.** Its
  copies are in the lobby under **Backups on this device**. The folder's own `host…wav`
  keeps the placeholder header a closing page leaves, so the 2.8 snippet shows a
  mismatch for it, and nothing repairs it.
- **A host recording alone whose connection to the room drops ends the session:** guests
  set as not recorded are forgotten and arrive as recorded. **Continue alone** is not
  remembered after a reload.
- **A guest who joins a running take cannot be set as not recorded until the take
  ends.**
- **A PDF shows no line while it opens.** A page that takes over 10 s to draw or fails,
  and a picture that cannot be decoded, is a black slide that still counts; pages past
  1000 are left out; a picture over 50 megapixels or in JPEG 2000 can be missing from
  its page; text in a font the PDF does not embed is drawn in a local font; links and
  text in the PDF cannot be clicked or selected.
- **The Previous and Next row is not always on screen:** not while the presenter waits
  alone, and not on a phone while chat covers the stage. Only the presenter turns
  slides, and a slide change drops no marker.
- **With incoming video stopped only the first presented screen carries the note and
  Show video;** the others are black tiles that still play their sound.
- **A presented video keeps sounding while its presenter waits alone** ("Everyone else
  left"), until someone joins or Leave.
- **The media board is empty after a reload,** and a looping pad stops. A looping pad
  cannot be stopped from the waiting room; it plays until someone joins or Leave.
- **A ready sound plays at the level it was made at;** Soft bed is quiet. A shipped
  sound whose button is clicked, then the board closed and opened before the download
  ends, is offered again; a second click adds it twice.
- **Levels are this tab's, by connection.** A level is forgotten when that person
  reconnects and on a reload; a fader only turns down; a shared screen or presented
  video has no fader; the meters move only while Levels is open, follow what arrives
  (not the fader) and have no clipping colour; **M** marks nothing while a fader or a
  list has the keyboard.
- **A speaker that goes away, or that the browser refuses, is forgotten;** plugging it
  in again does not bring it back. The two warning beeps play on the system default. A
  producer has no speaker picker. The lobby has no test sound and reads its list of
  outputs once. Two tabs do not share a change of speaker.
- **A guest's marker or note is lost while the host is not recording** (after a reload,
  before Resume) or while the guest's own connection is down; the guest's count still
  rises. A note still being typed when the take ends is dropped. A producer and a guest
  whose browser cannot record have no marker controls.
- **The rundown cannot be changed during a take,** and the lobby and waiting room have
  none. A length written `2 min` stays part of the segment's name; an hour or more is
  shown with hours (`90:00` reads `1:30:00`). It starts over after a pause.
- **Only the host's page says Paused.** After a reload the button reads Record and the
  next take's files carry no `_take<n>`; a guest whose page missed the stop keeps
  recording into its backup until the next take. While the teleprompter scrolls two
  buttons read Pause: the teleprompter's stops the script, the bar's ends the take.
  Pause has no key.
- **Shortcut keys exist only on the call screen and follow the keyboard layout:** a
  layout without Latin letters has no A, V, C, T, M or N, and its Alt+R and Alt+S are
  the keys where QWERTY has R and S. A letter typed after clicking outside the chat
  field is a key press. Below 640 px there is no **?** list and the single keys cannot
  be turned on or off in the call. A desktop that takes a chord never passes it on; a
  guest's Stop and save has no key.
- **A file recorded with no camera sits in the camera file's place:** the track panel
  calls it "Camera", a returned backup of it is named `…_camera_…`, and the page after
  leaving calls its backup "Backup video".
- **Microphone only is remembered per room and per browser.** While it is pressed the
  lobby's storage figures still count a camera file, and a person whose camera never
  started gets no Speaker row in the lobby.
- **A room of five to eight people is for the microphone only.** A browser that blocks
  storage starts the lobby on the camera, and joining that way a room of five or more
  reads "This room is full". The lobby's size figures and the take's 50 call-copy files
  are still those of a four-person room.
- **Echo cancellation is chosen in the lobby.** To turn it on or off, leave the call
  and join again.
- **The echo-cancellation mark is missing** from a take saved from its crash copy, from
  files from before a host reload, from a guest's own backup and from the call-audio
  copy; the audio is the same.
- **`nameTags` lists only recorded people,** and after a host reload only the titles of
  people who were there after it.
- **The program command shows cameras only,** in one fixed grid with no names and no
  screens; a returned backup is not in it and a file that ended early stays as a still
  picture. After a resume the host's tile is black until the reload, and with an empty
  resumed WAV the host's voice after the reload is missing. It stops in `ffmpeg` on a
  camera file with no sound and no WAV, and on a file with no picture that is not marked
  audio only; the sync file's note says how to take that file out.
- **A backup is offered by itself only after the host's stop.** A guest who left, whose
  tab the room closed or whose take a later take ended keeps it in the lobby with
  **Send to host**. A backup held in memory only is not in the lobby (the done line has
  the download link), and no page offers one of a screen. A screen recording that fell
  behind and a Present-only device's are not offered; a guest set as not recorded
  offers nothing.
- **An offered backup is the whole take again, on the call's uplink;** it waits while
  that guest's next take records. More than eight offers waiting are turned away. A
  returned backup is not paused while the host records.
- **A take sent later leaves the host nothing of that guest until the backup is saved.**
  After **Not now**, or if the guest leaves first, it is only in the guest's lobby.
  Turned on during a take, up to 16 MiB already handed to the browser still goes out.
  The choice is not remembered and the host is not asked.
- **A take sent later can confuse the track panel:** a screen share's row can read "Not
  receiving for …", the button reads "Check tracks", the guest's notice reads "Sending
  your last few seconds to the host." while nothing is sent, and a screen stretch that
  already arrived whole is offered again.
- **Only the host can be sent a file.** A sender cannot take an offer back, and can
  offer again after **Not now**. A file arriving when the host reloads is lost (an empty
  file of its name can stay), a sent file is in no take (not in the summary, sync file
  or chat log), and a sender waiting alone is told nothing of an offer still open.
- **A private message is not confirmed.** In the first moment of a connection it reads
  "Not delivered"; one handed over as a connection drops is lost with no sign. It shows
  on a shared screen and in that screen's recording. One that arrives while chat is
  open does not move **To**, and chat opened on Everyone is addressed to the sender of
  the newest private message that arrived while it was closed.
- **A teleprompter script is sent once.** Someone who joins or reloads afterwards
  asks the host to send it again.
- **Using the host's script replaces your own for that room, with no way back;** its
  reading time counts words by spaces.
- **A raised hand stays up until its owner lowers it** (a reload lowers it). While a
  screen is presented in a window narrower than 768 px only the first other person has
  a tile, so another person's hand is not on screen.
- **A reaction is drawn only on a tile and is not read out by a screen reader;** a
  window narrower than 640 px has no menu; one sent while the connection to the room is
  down is lost with no sign.
- **A person who reconnects has one line per connection in `recordingNotice`.**
- **Pop out floats one person, never a screen,** as the bare picture with no initial
  when their camera is off; someone presenting their entire screen shows the small
  window to the call and in that screen recording.
- **The framing guide divides the preview, which crops a 4:3 camera:** the recording
  has a little more above and below than the lines show.
- **Camera settings are not remembered;** Reset goes back to the values at the panel's
  opening; a lobby change of camera, quality, frame rate or echo cancellation reopens
  the camera and the sliders show that capture. Brightness, contrast, saturation,
  sharpness and focus have no control. A long exposure lowers the frame rate, Pan moves
  the other way on the mirrored self-view, and M and N mark nothing while a slider has
  the keyboard. After a lobby camera setting, a camera switched to in the call gets the
  rate the lobby camera delivered.
- **Add to calendar is only in the host's lobby,** one hour with fixed text, and
  accepts a start in the past. The room knows nothing of the entry; it holds the invite
  link (Google Calendar is handed it), and opened in another browser the host is a
  guest with no Record button.
- **A title is typed in the lobby for one visit** and cannot be changed in the call; a
  producer and a Present-only device have none.
- **The look (name tag colour and logo) is chosen only in the host's lobby, in one
  browser.** A change needs the host to leave and join again; while the host is away a
  newcomer sees the plain look; the waiting room and lobby preview have neither; a
  notice can cover the logo on a phone; an entire-screen share shows the logo.
- **Nobody is told that someone stopped incoming video,** and the choice is not
  remembered after a reload.
- **The host is not told the answer to a Help ask.** An ask reaching a page that still
  reads "Connecting…" shows once the call screen does. A restart gives the person a
  fresh id: a separate screen file, and their Levels fader and **To** choice are
  forgotten. A person who joined with the microphone only gets the camera ask, and
  their menu reads "You joined without a camera. To use one, leave and join again."
- **The record-alone page has no elapsed clock and no microphone warnings,** records
  the channels the microphone delivers (the call's Mono/Stereo choice does not apply),
  and does not keep the room alive. The browser may clear its storage under pressure;
  **Download** is the second copy.

## When something fails

1. Grab **both** consoles — most failures here are silent on one side.
2. Note the exact ordering (who joined first, who pressed what, when).
3. `ffprobe` every file produced, including the 0-byte ones.
4. Keep the folder — a partial file is evidence.
5. File it with the row number from this document.
